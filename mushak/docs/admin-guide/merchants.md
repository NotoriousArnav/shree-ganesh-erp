# Managing merchants

A merchant is one shop. Platform administrators create shops, edit their
details, and provision the first owner. After that, the owner manages products,
staff and settings from the shop area.

## List shops

The **Merchants** table on `/admin` shows every shop:

| Column | Meaning |
| --- | --- |
| **Name** | Display name used across the app. |
| **Slug** | URL-safe identifier, unique across the platform. |
| **GSTIN** | Shop GST number, or a dash. |
| **Phone** | Shop contact number, or a dash. |
| **Currency** | Price label for the shop. |
| **Edit** | Opens the edit dialog. |

The count beside the heading is the total number of shops.

## Create a shop and owner

Choose **Add merchant** and fill in the dialog:

| Field | Required | Notes |
| --- | --- | --- |
| **Shop name** | Yes | The owner can change it later in Settings. |
| **Owner name** | No | Defaults to `Shop Owner` when blank. |
| **Owner phone (optional)** | No | Also saved as the shop phone. Enables phone sign-in. |
| **Owner email** | Yes | Sign-in identifier; must be unique across the platform. |
| **Owner password** | Yes | At least 8 characters. Give it to the owner out of band. |

**Create merchant** performs two API calls:

1. `POST /api/admin/merchants` creates the shop. The slug is generated from the
   name because the dialog does not ask for one.
2. `POST /api/admin/merchants/{merchantId}/users` creates the owner with the
   `merchant` role and every shop permission.

If the second call fails, the shop remains without an owner. Create the owner
again from the API (see below) rather than creating a duplicate shop.

The owner signs in at `/login` and lands on the shop Dashboard. They can then
add staff from **Staff**.

## Edit a shop

Choose **Edit** on a row:

| Field | Notes |
| --- | --- |
| **Shop name** | Required, up to 120 characters. |
| **Slug** | Lowercase letters, numbers and dashes. Unique. |
| **GSTIN** | Optional, up to 20 characters. |
| **Phone** | Optional, up to 24 characters. |
| **Currency** | Defaults to `INR`. Saved as entered. |

Saving updates the shop immediately. It does not notify the owner. Changes to
the currency label do not convert stored prices.

The shop address and profile picture are not in this dialog; the owner edits
them in **Settings**.

## Create a shop with the API

```bash
BASE=http://localhost:8080
JAR=/tmp/mushak-admin.cookies

# Sign in as a platform administrator.
curl -s -c "$JAR" -H 'content-type: application/json' \
  -d '{"email":"admin@mushak.local","password":"admin123"}' \
  "$BASE/api/auth/sign-in/email"

# Create the shop.
curl -s -b "$JAR" -H 'content-type: application/json' \
  -d '{"name":"Anime Point Siliguri","slug":"anime-point-siliguri","phone":"+919870000000","currency":"INR"}' \
  "$BASE/api/admin/merchants"
```

The response contains the new `id`. Use it to add the owner:

```bash
curl -s -b "$JAR" -H 'content-type: application/json' \
  -d '{
    "name":"Deepak Kothiyal",
    "email":"deepak@anime-point.in",
    "password":"a-strong-password",
    "phoneNumber":"+919870000000",
    "permissions":["stock","catalogue","categories"]
  }' \
  "$BASE/api/admin/merchants/<merchantId>/users"
```

For a shop owner, `permissions` is optional; the API defaults to every
permission. Owners always have full access at runtime regardless of the stored
list.

## Edit a shop with the API

```bash
curl -s -b "$JAR" -X PATCH -H 'content-type: application/json' \
  -d '{"name":"Anime Point","currency":"INR","phone":"+919870000001"}' \
  "$BASE/api/admin/merchants/<merchantId>"
```

Sending an empty object returns `400 No changes supplied`. Sending `null` for
`gstin`, `phone` or `address` clears the field.

## Slugs

- Generated by lowercasing the name, replacing runs of non-alphanumeric
  characters with `-`, trimming dashes and limiting to 60 characters.
- Must match `^[a-z0-9]+(?:-[a-z0-9]+)*$`.
- Unique across all shops. A duplicate returns `409`.
- The CLI can find a shop by slug, which makes the slug worth keeping stable.

## What a shop gets on creation

A new shop starts with:

- the shop row (name, slug, currency, optional GSTIN, phone and address);
- no categories, products, stock or movements;
- one owner account once you add it.

The owner sees an empty Dashboard and can start adding categories and products.

## Deleting a shop

There is no delete action in the admin UI. Deleting the `merchants` row cascades
to its categories, catalogue items, inventory rows, movements and user accounts.
Because that also deletes history and logins, do it only with a backup and a
clear request. Prefer deactivating accounts if the shop is merely dormant.

## Permissions

| Action | `super_admin` | `dev` | `merchant` | `staff` |
| --- | --- | --- | --- | --- |
| List shops | Yes | Yes | No | No |
| Create a shop | Yes | Yes | No | No |
| Edit a shop | Yes | Yes | Only via Settings for its own shop | No |
| Add an owner account | Yes | Yes | No | No |

See [Permissions](../reference/permissions.md) for the full matrix.
